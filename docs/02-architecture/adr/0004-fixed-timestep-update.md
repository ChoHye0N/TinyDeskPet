# ADR-0004: 고정 시간 간격 업데이트

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-01 |
| 관련 요구사항 | FR-12, FR-27, NFR-MAINT-01 |

## 맥락

중력 낙하, 점프, 이후의 SpringBone 물리는 시간 간격(`dt`)에 따라 결과가 달라집니다. 프레임마다 다른 `dt`를 쓰면

- 144Hz 모니터와 60Hz 모니터에서 점프 높이가 미세하게 달라지고,
- 창이 잠시 멈췄다 돌아오면 큰 `dt` 때문에 캐릭터가 바닥을 뚫거나 물리가 폭발하며,
- 테스트 결과가 실행 환경에 따라 달라집니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 가변 `dt` | 가장 단순 | 위 문제 |
| B. 가변 `dt` + 상한 클램프 | 폭발은 막음 | 재현성 문제는 남음 |
| **C. 고정 `dt`(1/60초) + 누적기, 프레임당 최대 스텝 제한** | 결정적(deterministic), 테스트 재현 가능 | 렌더 주사율과 업데이트 주기가 달라 보간이 필요할 수 있음 |

## 결정

**C**를 선택합니다. `core::FixedTimestep`이 프레임 경과 시간을 누적해 이번 프레임에 실행할 업데이트 횟수를 돌려줍니다. 한 프레임 최대 5스텝까지만 실행해 "죽음의 나선(spiral of death)"을 막습니다.

## 결과

- 좋아지는 점: 같은 입력이면 항상 같은 결과가 나오므로 `CharacterController` 테스트가 정확한 값을 검증할 수 있습니다.
- 감수하는 점: 144Hz 모니터에서는 업데이트가 없는 프레임이 생겨 움직임이 약간 끊겨 보일 수 있습니다.
- 후속 작업: 필요하면 `FixedTimestep::alpha()`(0~1 보간 계수)로 이전/현재 상태를 보간해 그립니다 (M1 선택 과제).
