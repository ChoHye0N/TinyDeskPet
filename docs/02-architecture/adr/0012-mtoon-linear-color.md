# ADR-0012: MToon 셰이딩과 선형 색공간 (셰이더에서 sRGB 변환)

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-08 |
| 관련 요구사항 | FR-26 |

## 맥락

지금까지는 모든 재질을 2단 툰(그림자 = 기본색 × 0.75)으로, 텍스처를 감마 공간 그대로 계산했습니다. VRM 모델은 재질마다 MToon 값(그림자 색·그림자 텍스처, 그림자 경계, 림, MatCap, 발광)을 갖고 있는데 이를 버리고 있었습니다. 예: kei는 옷·피부마다 그림자 전용 텍스처가 따로 있음. 또 MToon 값(VRM 1.0, glTF)은 선형 공간 기준이라 감마 공간에서 계산하면 섞이는 색이 어두워지고 그림자 경계가 달라집니다.

선형 공간으로 바꾸려면 출력할 때 sRGB로 되돌려야 합니다. 이 앱은 DirectComposition에 **premultiplied alpha**로 넘깁니다(ADR-0001). DWM은 "sRGB 색 × 알파"를 기대합니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 렌더 타깃을 `_SRGB` 형식으로 (하드웨어가 쓰기 때 변환) | 표준 방식. 블렌딩·MSAA resolve가 선형 공간 | 하드웨어는 알파를 곱한 값 c·a를 변환 → sRGB(c·a) ≠ sRGB(c)·a. 반투명 가장자리(MSAA 경계, 머리카락 끝)가 밝게 떠 바탕화면 위에서 흰 테두리 |
| **B. 텍스처만 `_SRGB`로 읽고, 셰이더 마지막에 직접 sRGB로 바꾼 뒤 알파를 곱함** | DWM이 기대하는 값과 정확히 같음. 렌더 타깃·합성 경로 변경 없음 | 반투명 블렌딩·MSAA 평균은 감마 공간 (예전과 같음) |
| C. 감마 공간 유지, MToon 값만 적용 | 변경이 가장 작음 | 선형 기준 값이라 색이 어긋남 |

## 결정

B. 텍스처를 `R8G8B8A8_UNORM_SRGB`로 만들어 샘플링 때 선형 값으로 읽고, 조명은 선형 공간에서 계산한 뒤, 픽셀 셰이더 마지막에 `linearToSrgb(색) × 알파`로 출력합니다.

MToon은 VRM 1.0 정의 하나로 통일합니다(`model::Material`). VRM 0.x 값은 읽을 때 변환합니다. 색은 sRGB → 선형으로 바꾸고, 그림자 경계(`_ShadeShift`, `_ShadeToony`)는 1.0의 shift·toony로 바꿉니다(경계의 중심·반폭이 같도록). MToon이 아닌 재질(PMX, FBX, 일반 glTF)도 같은 셰이더를 씁니다. 그림자 색은 기본색 × 0.53(선형, 예전 감마 0.75배와 같은 밝기), 경계는 ±0.05입니다.

구현한 MToon 항목은 다음과 같습니다.

- 그림자 색·텍스처, shading shift·toony
- 림(색, 프레넬 지수, 리프트, 조명 섞기)
- MatCap(시점 기준 법선으로 구 텍스처를 찍음)
- 발광(색·텍스처)

시점 방향은 화각이 20°로 좁아 모델 공간의 방향 하나로 근사합니다(`MeshCharacter::viewDirection`).

## 결과

- 좋아지는 점: VRM 제작자가 지정한 그림자 색·텍스처, 경계 위치가 그대로 보임. 밉맵이 선형 공간에서 평균되어 작은 밉이 어두워지지 않음
- 감수하는 점: 반투명 블렌딩·MSAA 평균은 감마 공간이라 엄밀한 선형 파이프라인은 아님. 간접광(GI)·그림자 받기·외곽선 조명 섞기·UV 애니메이션·노멀 맵은 생략 (빛 하나, 흰색, 강도 1)
- 후속 작업: VRM 1.0 `shadingShiftTexture`, `rimMultiplyTexture`. MMD 스피어 텍스처를 MatCap으로 연결
