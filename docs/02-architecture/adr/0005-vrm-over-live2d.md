# ADR-0005: 캐릭터 포맷으로 VRM 채택

| 항목 | 내용 |
|---|---|
| 상태 | 승인 (ADR-0009로 보완: PMX·FBX도 읽기) |
| 날짜 | 2026-10-01 |
| 관련 요구사항 | FR-22 ~ FR-28 |

## 맥락

최종 캐릭터 포맷을 정해야 합니다. 이 프로젝트의 목적은 **DirectX 렌더링 학습과 포트폴리오**이므로, 직접 구현할 수 있는 범위가 넓은 포맷이 유리합니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 2D 스프라이트 시트 | 가장 쉬움 | 렌더링 학습 가치가 낮음 |
| B. Live2D (Cubism SDK for Native) | 공식 D3D11 렌더러 제공, 2D 표현력 좋음 | 렌더링을 SDK가 대신함. Cubism Core가 독점 라이선스라 저장소에 포함 불가 |
| **C. VRM (glTF 2.0 확장)** | 공개 사양, 휴머노이드 본·표정·스프링본·MToon이 표준화됨. 파서·스키닝·셰이더를 직접 구현해야 함 | 구현량이 많음 |

## 결정

**C. VRM**을 채택합니다. glTF 파싱은 `cgltf`(단일 헤더, MIT)를 사용하고, VRM 확장(`VRM`, `VRMC_vrm`, `VRMC_springBone`, `VRMC_materials_mtoon`)은 직접 파싱합니다. VRM 0.x와 1.0을 모두 읽되 내부 표현은 1.0 기준으로 통일합니다.

## 결과

- 좋아지는 점: GPU 스키닝, 모프 타깃, 툰 셰이딩, 간단한 물리를 직접 구현하게 되어 그래픽스 포트폴리오로서 가치가 큽니다.
- 감수하는 점: M2~M5까지 구현량이 많습니다. 그 전까지는 플레이스홀더로 상호작용을 먼저 완성합니다.
- 후속 작업: 모델 파일은 저장소에 커밋하지 않습니다 (`assets/models/`는 `.gitignore`). 테스트용으로는 라이선스가 명확한 샘플만 사용하고 출처를 `assets/README.md`에 기록합니다.
