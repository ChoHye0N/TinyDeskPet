# ADR-0013: 모션 파일 재생 — 월드 델타로 통일한 리타기팅

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-08 |
| 관련 요구사항 | FR-20 (애니메이션), ADR-0010 후속 |

## 맥락

ADR-0010에서 동작을 코드로 계산했고, 모션 파일은 그 기반 위에 나중에 얹기로 했습니다. 사용자가 고를 만한 모션은 세 형식에 흩어져 있습니다.

| 형식 | 특징 |
|---|---|
| VRMA (VRM Animation) | glTF. 노드에 기본 자세 회전이 있을 수 있음. 정면 +Z |
| VMD (MMD) | 뼈대가 없고 본 이름(Shift-JIS)별 키만 있음. 왼손 좌표계, 베지어 보간. 다리는 대부분 足ＩＫ(발목 위치)로 움직임. 기본 자세가 A포즈 |
| FBX (Mixamo 등) | 노드마다 pre-rotation 등 로컬 축이 제각각. ufbx로 평가 |

대상 모델도 VRM(T포즈), PMX(A포즈), FBX로 기본 자세와 본 축이 다릅니다. 형식 × 대상마다 변환을 따로 만들면 조합이 늘어납니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 로컬 회전 그대로 복사 | 단순 | 본 축·기본 자세가 다르면 엉뚱한 방향. 형식마다 축 변환 필요 |
| B. 키프레임을 그대로 저장하고 재생할 때 형식별 보간 | 메모리 적음 | 재생 코드가 형식을 알아야 함 (베지어, 계단, IK) |
| **C. 읽을 때 "기본 자세 → 지금"의 모델 공간 회전(월드 델타)으로 바꿔 30fps로 다시 샘플링. 재생할 때 대상의 기본 자세로 보정** | 형식 차이(좌표계, 본 축, 보간, IK)를 로더 안에 가둠. 재생은 한 가지 | 길이 × 30 × 본 수만큼 메모리 (5분 = 약 4MB). 30fps 사이는 slerp |

## 결정

C. `model::MotionClip`은 휴머노이드 본마다 30fps 월드 델타 Δ와, 원본 기본 자세의 팔다리 방향을 갖습니다.

- **월드 델타**: Δ = W(t)·W₀⁻¹ (W: 노드의 월드 회전, W₀: 기본 자세). 모델 축 기준 회전이라 원본의 본 축·중간 본을 몰라도 됩니다.
- **VMD**: MMD 본은 기본 자세 회전이 없어 표준 MMD 뼈대 계층으로 로컬 회전을 곱하면 W입니다. 足ＩＫ 키가 있으면 표준 다리 길이로 2관절 IK를 풉니다. 무릎은 下半身 기준 앞, 다리 비틀림은 골반을 따라가고, 발 방향은 IK 본 회전을 씁니다. 좌표 변환(z 반전)은 쿼터니언 (x, y, z, w) → (−x, −y, z, w)이고, 팔의 기본 자세는 37° 아래로 가정합니다.
- **재생 (`anim::MotionPlayer`)**: 대상 본 j의 누적 회전은 트랙이 있으면 Aⱼ = Δ·C, 없으면 Aⱼ = A부모입니다. Skeleton 델타 = Aⱼ·A부모⁻¹입니다. C는 대상 팔다리 방향을 원본 기본 자세 방향으로 돌리는 회전이고, 방향을 모르는 본(손, 몸통)은 부모 쪽 C를 물려받습니다.
- **연결**: 동작(대기·걷기·매달림·공중)별로 `[animation] *_clip`에 파일을 지정합니다. 지정한 동작만 코드 대신 클립을 재생하고, 전환 보간·착지 웅크림·발 붙이기·흔들림은 그대로 적용됩니다. 위치(엉덩이 이동)는 쓰지 않습니다. 발 높이는 기존 발 붙이기(groundOffset)가 맞춥니다.

## 결과

- 좋아지는 점: VRMA·VMD·FBX 모션을 VRM·PMX·FBX 모델 어디에나 입힐 수 있음. 새 형식은 로더만 추가하면 됨
- 감수하는 점: 비틀림(본 축 회전)은 기본 자세 보정에서 방향만 맞추므로 원본과 조금 다를 수 있음. VMD는 표준 뼈대 비율을 가정 (다리 IK의 무릎 각도가 대상과 조금 다를 수 있음). 손가락·표정 트랙·루트 이동은 읽지 않음. 30fps보다 촘촘한 키는 손실
- 후속 작업: 손가락 본, VRMA 표정, 걷기 클립의 보폭과 이동 속도 맞추기
