# ADR-0015: 일반 glTF의 본 이름 매핑과 파일 안 애니메이션 고르기

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-13 |
| 관련 요구사항 | FR-20 (애니메이션), ADR-0009·ADR-0014 보완 |

## 맥락

게임·DCC 도구에서 내보낸 GLB(예: 3ds Max Biped 뼈대 + 애니메이션 27개)를 그대로 넣으면 두 가지가 막혔습니다.

| 막힌 것 | 원인 |
|---|---|
| 모델의 휴머노이드 본 0개 → 동작·모션이 붙지 않음 | glTF는 VRM `humanBones`로만 매핑. FBX·PMX가 쓰는 본 이름 매핑을 glTF에는 쓰지 않음 |
| 파일 안 애니메이션을 모션으로 못 씀 | glTF 모션은 `VRMC_vrm_animation`이 없으면 오류. 있어도 첫 애니메이션만. FBX도 첫 애니메이션 스택만 |

그래서 VRM으로 변환하고 클립마다 VRMA로 따로 뽑아야 했습니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 지금처럼 변환 도구에 맡김 | 코드 변경 없음 | 모델·클립마다 변환 작업. 변환하면서 비휴머노이드 본 트랙이 빠지기도 함 |
| B. 클립마다 별도 설정 키 (`idle_clip_name = …`) | 파싱이 단순 | 키가 동작 수만큼 늘어남. 경로와 이름이 떨어져 있어 읽기 어려움 |
| **C. VRM이 아닌 glTF는 본 이름으로 매핑, 클립은 `파일#이름`으로 고름** | 설정 한 줄로 끝. 같은 파일을 모델·모든 모션에 씀. glTF·FBX에 같은 문법 | 이름에 `#`이 든 파일과 겹침 → 경로 전체가 파일이면 파일로 봄. 설정 파서가 `#`을 주석으로 자르지 않게 해야 함 |

## 결정

C.

- **모델 매핑**: VRM(0.x·1.0)이면 지금처럼 `humanBones`만 씁니다(이름은 보지 않음). VRM이 아닌 glTF는 노드 이름을 FBX 규칙(Mixamo·3ds Max Biped), 아니면 MMD 이름으로 매핑합니다. 한 휴머노이드 본에 여러 노드가 맞으면 처음 것만 씁니다.
- **모션 매핑**: glTF 모션은 `VRMC_vrm_animation` → VRM 모델의 `humanBones` → 본 이름 순으로 찾습니다. 하나도 없으면 오류입니다. 확장이 없는 클립의 형식은 `MotionFormat::Gltf`입니다.
- **클립 고르기**: `loadMotionFile("a.glb#Cafe_Idle")`은 glTF `animations[].name`, FBX 애니메이션 스택 이름이 같은 것을 읽습니다. 이름을 빼면 첫 번째, 없는 이름이면 있는 이름을 모두 나열한 오류입니다. VMD는 이름을 주면 오류입니다(잘못된 설정을 조용히 넘기지 않음). 경로 전체가 있는 파일이면 `#`도 파일 이름입니다.
- **설정 주석**: `;` `#`은 줄 맨 앞이나 공백 뒤에 올 때만 주석입니다. 값 안의 `#`(클립 이름)과 `;`(경로)을 지킵니다.
- **FBX 재생 구간**: 스택에 재생 구간이 없으면 그 스택 레이어의 곡선만으로 길이를 잽니다(전에는 파일의 모든 곡선이라, 스택이 여럿이면 길이가 섞임).

## 결과

- 좋아지는 점: 게임에서 내보낸 GLB 하나로 모델과 모든 동작을 설정할 수 있음. 비휴머노이드 본(머플러·치마 등) 트랙도 같은 파일이라 이름이 그대로 맞음
- 감수하는 점: 모션 파일이 모델과 같은 큰 파일이면 동작마다 파일을 다시 읽음(7.8MB GLB 기준 동작당 약 0.05초, 시작할 때만). SpringBone 정보는 GLB에 없어 흔들림은 붙지 않음. 값 안에 공백 뒤 `;` `#`을 쓰는 경로는 여전히 잘림
- 후속 작업: 모델 파일 한 번만 읽고 여러 클립 꺼내기(필요해지면), 이름 기반 흔들림 본 추정
