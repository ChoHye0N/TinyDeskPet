# ADR-0015: 일반 glTF의 본 이름 매핑, 소품 메시 버리기, 파일 안 애니메이션 고르기

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-13 |
| 관련 요구사항 | FR-20 (애니메이션), ADR-0009·ADR-0014 보완 |

## 맥락

게임·DCC 도구에서 내보낸 GLB(예: 3ds Max Biped 뼈대 + 애니메이션 27개)를 그대로 넣으면 세 가지가 막혔습니다.

| 막힌 것 | 원인 |
|---|---|
| 모델의 휴머노이드 본 0개 → 동작·모션이 붙지 않음 | glTF는 VRM `humanBones`로만 매핑. FBX·PMX가 쓰는 본 이름 매핑을 glTF에는 쓰지 않음 |
| 파일 안 애니메이션을 모션으로 못 씀 | glTF 모션은 `VRMC_vrm_animation`이 없으면 오류. 있어도 첫 애니메이션만. FBX도 첫 애니메이션 스택만 |
| 총·이펙트 소품이 엉뚱한 곳(바닥, 몸 옆)에 남고 캐릭터가 작아짐 | 소품은 몸 뼈대 밖(뼈대 맨 위, 장면 최상위)의 별도 뼈에 붙어 있고, 게임은 평소 애니메이션에서 그 뼈의 크기를 0.02배로 줄여 숨김. 크기 키를 읽지 않으니 기본 자세 그대로 남고, 화면 맞춤 영역도 소품만큼 넓어짐 |

그래서 VRM으로 변환하고 클립마다 VRMA로 따로 뽑아야 했습니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 지금처럼 변환 도구에 맡김 | 코드 변경 없음 | 모델·클립마다 변환 작업. 변환하면서 비휴머노이드 본 트랙이 빠지기도 함 |
| B. 클립마다 별도 설정 키 (`idle_clip_name = …`) | 파싱이 단순 | 키가 동작 수만큼 늘어남. 경로와 이름이 떨어져 있어 읽기 어려움 |
| **C. VRM이 아닌 glTF는 본 이름으로 매핑, 몸 밖 소품은 버리고 몸 안 소품은 클립의 크기 0 키로 숨김, 클립은 `파일#이름`으로 고름** | 설정 한 줄로 끝. 같은 파일을 모델·모든 모션에 씀. glTF·FBX에 같은 문법 | 이름에 `#`이 든 파일과 겹침 → 경로 전체가 파일이면 파일로 봄. 설정 파서가 `#`을 주석으로 자르지 않게 해야 함 |

## 결정

C.

- **모델 매핑**: VRM(0.x·1.0)이면 지금처럼 `humanBones`만 씁니다(이름은 보지 않음). VRM이 아닌 glTF는 노드 이름을 FBX 규칙(Mixamo·3ds Max Biped), 아니면 MMD 이름으로 매핑합니다. 한 휴머노이드 본에 여러 노드가 맞으면 처음 것만 씁니다.
- **모션 매핑**: glTF 모션은 `VRMC_vrm_animation` → VRM 모델의 `humanBones` → 본 이름 순으로 찾습니다. 하나도 없으면 오류입니다. 확장이 없는 클립의 형식은 `MotionFormat::Gltf`입니다.
- **클립 고르기**: `loadMotionFile("a.glb#Idle")`은 glTF `animations[].name`, FBX 애니메이션 스택 이름이 같은 것을 읽습니다. 이름을 빼면 첫 번째, 없는 이름이면 있는 이름을 모두 나열한 오류입니다. VMD는 이름을 주면 오류입니다(잘못된 설정을 조용히 넘기지 않음). 경로 전체가 있는 파일이면 `#`도 파일 이름입니다.
- **설정 주석**: `;` `#`은 줄 맨 앞이나 공백 뒤에 올 때만 주석입니다. 값 안의 `#`(클립 이름)과 `;`(경로)을 지킵니다.
- **소품 메시 버리기**: VRM이 아닌 glTF에서 휴머노이드를 찾았을 때, 스킨 관절이 모두 엉덩이(hips) 본 아래 밖에 있는 메시(스킨이 없으면 메시 노드 자체가 밖에 있는 메시)는 읽지 않습니다(`Model::droppedProps`에 이름, 로그에 표시). 총·이펙트 소품이 여기에 해당하고, 머리 뼈 아래 헤일로나 몸에 스킨된 장신구는 남습니다. 크기 키로 숨기는 방식(대안: 비휴머노이드 본의 크기 트랙 재생)은 게임과 같지만, 총을 쓰는 동작(편성 대기 등)에서는 총이 다시 보이고 화면 맞춤 영역도 계속 넓어서 택하지 않았습니다. 총이 손 뼈 아래에 붙은 모델은 장신구와 구조가 같아 걸러지지 않습니다(그런 모델이 나오면 메시 이름 설정을 추가).
- **숨김 본**: 몸 안에 붙은 소품(엉덩이 아래 총알 등)은 위 규칙으로 걸러지지 않음. glTF 모션에서 크기 키가 모두 0.1배 미만인 휴머노이드가 아닌 본을 `MotionClip::hiddenBones`에 담고, 그 클립을 재생하는 동안 그 본과 아래 본의 스킨 행렬을 크기 0으로 접어 숨깁니다(`Skeleton::computeSkinMatrices`의 `hidden`). 클립이 없는 동작은 불러온 클립 중 하나라도 숨기는 본을 숨깁니다. 크기 트랙 전체를 재생하는 대신 "숨김"만 다룬 것은 회전만 쓰는 지금 규약(ADR-0013)을 바꾸지 않기 위해서입니다.
- **이름 본 이동 (glTF 사양 기능)**: 눈꺼풀·눈썹처럼 이동 키로 움직이는 본. 휴머노이드가 아닌 노드의 (로컬 이동 − 기본 자세 로컬 이동)을 부모의 기본 자세 월드 행렬로 모델 축에 옮겨 `NamedTrack::offsets`에 담고, 재생할 때 대상/원본 엉덩이 높이 비율을 곱해 `Skeleton::computePose`의 `offsets`로 더합니다(Pⱼ = P부모 + A부모(pⱼ − p부모 + offsetⱼ)). 엉덩이 높이는 엉덩이가 움직이지 않아도 기록합니다. 크기 키는 숨김 외에는 아직 재생하지 않습니다.
- **모프 가중치 애니메이션 (glTF 사양 기능)**: `weights` 채널을 타깃별 `WeightTrack`(노드 이름 + 타깃 번호)으로 읽고, 일반 glTF 모델은 메시 노드의 모프 타깃을 `Model::morphs`(같은 이름 + 번호)로 보관합니다. 재생기가 이름으로 연결하고 렌더러가 표정 모프와 함께 더합니다. 입 모양 메시마다 "숨기기" 타깃을 두고 가중치 0/1로 하나만 보이게 하는 모델이 이것으로 동작합니다. VRM은 표정(`expressions`)만 씁니다. 사양의 기본값(0)으로는 클립이 가중치를 주지 않을 때 그런 모델의 입이 모두 보이므로, 모델 파일 안 첫 애니메이션의 첫 키를 `NamedMorph::defaultWeight`로 두고 클립에 트랙이 없는 모프(또는 클립이 하나도 없을 때)에 씁니다.
- **클립이 없는 동작의 이름 본**: 머플러·꼬리처럼 이름 트랙으로 움직이는 본은 코드로 만든 자세(공중 등)에서 기본 자세 그대로 남는데, 게임 모델은 기본 자세에서 이런 본이 수평으로 뻗어 있습니다. 클립(대기 우선)의 첫 프레임 모양을 부모 기준 델타로 씁니다. 이동 오프셋과 모프 가중치(입 모양)도 같은 첫 프레임 값을 씁니다.
- **기본 창 크기**: 배포 설정의 기본 창을 640×680(전의 320×340을 200%로)으로 키웁니다. VRM으로 변환한 참고 모델을 사용자가 200%로 두고 쓴 크기입니다.
- **FBX 재생 구간**: 스택에 재생 구간이 없으면 그 스택 레이어의 곡선만으로 길이를 잽니다(전에는 파일의 모든 곡선이라, 스택이 여럿이면 길이가 섞임).

## 결과

- 좋아지는 점: 게임에서 내보낸 GLB 하나로 모델과 모든 동작을 설정할 수 있음. 비휴머노이드 본(머플러·치마 등) 트랙도 같은 파일이라 이름이 그대로 맞음. 소품이 빠져 VRM으로 변환한 모델과 같은 크기로 보임
- 감수하는 점: 기본 창이 커져 200%에서는 1280×1360으로 화면보다 높아질 수 있음(크기 메뉴로 줄임). 숨김 본·이름 본 이동·모프 가중치는 glTF 모션만 읽음(FBX는 아직). 모프 가중치는 30fps로 다시 샘플링해 STEP 키 사이 한 프레임은 섞일 수 있음. 모델 파일에 애니메이션이 없고 클립도 가중치를 주지 않으면 기본값이 0이라, 입 모양 메시를 가중치로 고르는 모델은 입이 겹쳐 보임(메시 `weights` 기본값은 아직 읽지 않음). 모션 파일이 모델과 같은 큰 파일이면 동작마다 파일을 다시 읽음(7.8MB GLB 기준 동작당 약 0.05초, 시작할 때만). SpringBone 정보는 GLB에 없어 흔들림은 붙지 않음. 값 안에 공백 뒤 `;` `#`을 쓰는 경로는 여전히 잘림
- 후속 작업: 모델 파일 한 번만 읽고 여러 클립 꺼내기(필요해지면), 이름 기반 흔들림 본 추정
