# ADR-0008: VRM 모델 표시를 M1 상호작용보다 먼저 진행

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-01 |
| 관련 요구사항 | FR-22 ~ FR-28, ADR-0005 |

## 맥락

원래 로드맵은 M1(상호작용) → M2(D3D11 3D 기초) → M3(VRM 로딩) 순서였습니다. 그러나 슬라임 플레이스홀더만으로는 결과물의 동기 부여와 시연 가치가 낮아, **공개된 서브컬처 VRM 모델(Seed-san)을 먼저 화면에 띄우기로** 했습니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 원래 순서 유지 | 로드맵 그대로 | 캐릭터가 오랫동안 슬라임 |
| B. 스프라이트 시트로 임시 표시 | 빠름 | ADR-0005와 어긋나고 버려질 코드 |
| **C. M2·M3의 최소 범위를 앞당김** | 최종 구조(VRM + D3D11) 위에서 진행, 버릴 코드 없음 | 상호작용 과제(M1)가 뒤로 밀림 |

## 결정

**C**를 택합니다. 새 마일스톤 **M1a "VRM 정적 표시"**를 M1 앞에 둡니다.

- `model` 모듈(플랫폼 독립): cgltf로 VRM 0.x/1.0을 읽어 정점·인덱스·머티리얼·텍스처(인코딩된 PNG/JPEG 바이트)를 만듭니다. 바인드 포즈는 로드 시 CPU 스키닝으로 굽고, VRM 0.x는 Y축 180° 회전으로 1.0의 정면(+Z)에 맞춥니다.
- `renderer`: HLSL을 빌드 시 `fxc`로 바이트코드 헤더로 컴파일하고, `MeshPass`(깊이 버퍼, premultiplied alpha, 단순 툰 셰이딩)를 추가합니다. 텍스처 디코딩은 WIC를 씁니다.
- `app`: 모델 경계 상자에 맞춘 카메라를 계산해 `RenderScene`으로 넘깁니다. 모델이 없거나 로드에 실패하면 슬라임으로 대신 그립니다.

범위 밖: 애니메이션·표정(M4), MToon·SpringBone(M5), 선형 색공간(M5에서 sRGB 처리와 함께).

## 결과

- 좋아지는 점: 첫 결과물부터 실제 캐릭터가 보입니다. M2·M3의 핵심(파이프라인, glTF 구조)을 일찍 학습합니다.
- 감수하는 점: T포즈로 정지한 채 표시됩니다(팔 내리기는 스키닝 애니메이션이 필요한 M4). 히트 영역은 창 크기 기준 타원으로 근사합니다.
