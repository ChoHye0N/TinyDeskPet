# ADR-0009: VRM 외에 PMX·FBX 모델 형식 지원

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-01 |
| 관련 | [ADR-0005](0005-vrm-over-live2d.md) (보완), [ADR-0008](0008-vrm-before-interaction.md) |

## 맥락

ADR-0005에서 캐릭터 형식을 VRM으로 정했습니다. 그러나 사용자가 가진 모델은 MMD(PMX)나 FBX인 경우가 많고, 특히 모션 자료(MMD의 VMD, Mixamo의 FBX)가 이 두 형식에 풍부합니다. 매번 외부 도구로 VRM으로 변환하게 하는 대신 프로그램이 직접 읽기를 원합니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. VRM만 유지, 변환은 사용자가 | 구현 없음 | 변환 도구(Blender, PMX Editor) 사용 부담 |
| B. 실행 시 PMX/FBX → VRM 파일로 변환해 저장 | 변환 결과 재사용 | VRM 쓰기(glTF 직렬화)까지 구현해야 함. 원본 라이선스상 개조·재배포 문제 |
| **C. 형식별 로더 → 공통 내부 모델(`model::Model`)** | 렌더러·앱 변경 없음. 형식 추가가 로더 하나 | 형식마다 좌표·단위 차이를 직접 맞춰야 함 |

## 결정

**C**를 택합니다.

- 진입점 `loadModelFile`이 매직 바이트(+ ASCII FBX는 확장자)로 형식을 판별해 형식별 로더로 보냅니다.
  - glTF/GLB/VRM: 기존 cgltf 로더
  - PMX 2.0/2.1: 직접 구현 (사양이 단순한 바이너리, 학습 가치)
  - FBX(바이너리·ASCII): **ufbx** v0.23.1 (단일 파일 C, MIT/퍼블릭 도메인). FBX SDK는 독점 라이선스·대용량이라 제외
- 모든 로더는 공통 규약(미터, 오른손, +Y 위, 정면 +Z, CCW 앞면, UV 원점 왼쪽 위)으로 맞춰 반환합니다.
- 외부 텍스처 파일(PMX, FBX, .gltf)은 모델 파일 폴더 기준으로 읽습니다. WIC가 못 읽는 TGA는 **stb_image**(TGA 전용 빌드)로 미리 RGBA로 풉니다.
- 애니메이션(M4)을 형식과 무관하게 만들기 위해 본 이름을 **휴머노이드 본**(VRM 이름 체계)으로 통일합니다. VRM은 `humanBones`, PMX는 일본어 표준 본 이름, FBX는 Mixamo 이름을 매핑합니다.

범위 밖: PMD(구 MMD 형식), OBJ, 모프·물리(PMX 강체), MMD 툰·스피어 텍스처, FBX 애니메이션.

## 결과

- 좋아지는 점: 사용자가 가진 모델 대부분을 바로 띄울 수 있고, 이후 VMD·FBX 모션 재생의 기반이 생깁니다.
- 감수하는 점: 서드파티 의존성 2개(ufbx, stb) 추가. 형식마다 셰이딩 정보가 달라 외형은 "기본색 + 텍스처" 수준으로 통일됩니다. MMD 모델은 이용 규약이 엄격한 경우가 많아 사용자가 직접 확인해야 합니다.
