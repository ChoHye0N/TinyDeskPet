# ADR-0010: 코드로 계산하는 휴머노이드 애니메이션과 GPU 스키닝

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-01 |
| 관련 | [ADR-0009](0009-multiple-model-formats.md), ROADMAP M4 |

## 맥락

VRM·PMX·FBX 모델 대부분은 모션 데이터를 담고 있지 않습니다. 지금까지는 로드할 때 바인드 포즈(T/A포즈)를 정점에 구워 넣어 정지한 채 표시했습니다. 캐릭터 상태(대기·걷기·매달림·공중)에 맞춰 실제로 움직이게 하고 싶습니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 모션 파일 재생 (VRMA, VMD, FBX 애니메이션) | 자연스러운 동작 | 라이선스가 명확한 모션 파일이 필요. 형식별 리타기팅 구현이 큼 |
| **B. 휴머노이드 본 회전을 코드로 계산** | 외부 파일 없음. 형식과 무관(ADR-0009의 공통 본 이름 사용). 상태와 바로 연결 | 동작이 단순함 |
| C. CPU 스키닝 후 매 프레임 정점 버퍼 갱신 | 셰이더 단순 | 정점 수만큼 CPU 비용, 큰 버퍼 업로드 |

## 결정

**B + GPU 스키닝**을 택하고, A(모션 파일)는 이 기반 위에 나중에 얹습니다.

- **회전 규약**: 본마다 "모델 공간 축 기준 델타 회전"을 주고, 부모 자세 위에 누적합니다 (`Aⱼ = Δⱼ × A부모`). 원본 본의 로컬 축을 몰라도 되므로 VRM·PMX·FBX를 같은 코드로 움직입니다.
- **팔 내리기**: 위팔의 바인드 방향(위팔 → 아래팔)에서 목표 방향으로 `fromTo` 회전. T포즈든 A포즈든 같은 결과가 됩니다.
- **스킨 행렬**: `Sⱼ = T(-pⱼ) · R(Aⱼ) · T(Pⱼ)`. 정점은 이미 바인드 포즈 모델 공간에 있으므로 역바인드 행렬이 단순한 이동이 됩니다.
- **GPU**: 정점에 본 4개 인덱스·가중치를 두고 정점 셰이더에서 선형 블렌드 스키닝. 스킨 행렬은 구조화 버퍼(본 수 제한 없음).
- **표정**: 깜빡임·기쁨·놀람만 지원. 형식별 모프(VRM expressions/blendShape, PMX 정점 모프)를 희소 델타로 모으고, 가중치가 바뀐 프레임에만 CPU에서 합산해 두 번째 정점 스트림으로 올립니다.
- **새 모듈 `anim`**: `Skeleton`(FK·스킨 행렬), `ProceduralAnimator`(상태 → 본 회전·표정). character와 서로 모르도록 app이 상태를 변환합니다 (SAD 규칙 R3).

## 결과

- 좋아지는 점: 모든 형식의 모델이 대기(숨쉬기), 걷기(팔다리 교차), 매달림(대롱대롱 + 놀람), 공중(팔 벌림), 착지(무릎 굽힘), 깜빡임을 합니다.
- 감수하는 점: 대기 동작 때문에 매 프레임 그리게 되어 Present 생략(DEBT-02)의 효과가 줄어듭니다 → `[animation] idle_motion = false`로 끌 수 있게 했습니다 (측정: GPU 1.6% → 0%). 손가락·머리카락(SpringBone)·물리는 움직이지 않습니다. 카메라는 T포즈 대신 실제로 취하는 자세들의 경계 상자에 맞춥니다.
