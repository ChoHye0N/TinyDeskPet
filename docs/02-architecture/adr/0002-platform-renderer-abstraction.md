# ADR-0002: 플랫폼·렌더러 인터페이스 분리와 의존성 주입

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-10-01 |
| 관련 요구사항 | NFR-PORT-01, NFR-MAINT-01 |

## 맥락

프로토타입은 Win32 코드, D3D 코드, 캐릭터 로직이 한 파일의 전역 변수로 얽혀 있었습니다. 이 상태로는

- 드래그·낙하 같은 로직을 창과 GPU 없이 테스트할 수 없고,
- 렌더러를 플레이스홀더에서 VRM으로 바꿀 때 모든 코드를 건드려야 하며,
- 나중에 macOS(Metal) 백엔드를 추가할 수 없습니다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 단일 파일/전역 상태 유지 | 코드가 가장 짧음 | 테스트 불가, 확장 불가 |
| B. `#ifdef _WIN32`로 곳곳에서 분기 | 추상화 비용 없음 | 분기가 코드 전체에 퍼짐 |
| **C. 인터페이스(`IWindow`, `IRenderer`) + 생성자 주입** | 로직을 가짜(Fake) 구현으로 테스트 가능, 백엔드 교체 용이 | 가상 함수 호출 비용(프레임당 수십 회 수준이라 무시 가능), 파일 수 증가 |

## 결정

**C**를 선택합니다. `Application`은 `std::unique_ptr<IWindow>`와 `std::unique_ptr<IRenderer>`를 생성자로 받습니다. 구체 타입을 아는 곳은 `main_win32.cpp` 하나뿐입니다.

## 결과

- 좋아지는 점: `tests/app/ApplicationTests.cpp`가 `FakeWindow`, `FakeRenderer`로 메인 루프를 Linux CI에서 검증합니다. Metal 백엔드는 `IWindow`/`IRenderer` 구현 두 개만 추가하면 됩니다.
- 감수하는 점: 인터페이스에 Win32 전용 개념이 새어 들어가지 않도록 신경 써야 합니다 (예: `HWND` 대신 `void* nativeHandle()`).
- 후속 작업: 인터페이스가 커지면 역할별로 나눕니다 (예: `ITrayIcon`).
